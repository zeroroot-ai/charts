# The OpenBao seed contract (deploy#1732). ONE definition.
#
# The openbao-auto-init sidecar reads this table and makes sure every key
# exists in the kv v2 mount `secret` at `secret/data/<key>` with every
# property listed. helm/gibson-workloads/tests/lib/check_seed_coverage.py
# reads the same table and fails the build when a profile renders an
# ExternalSecret that reads a key or a property this table does not seed.
#
# Format: one key per line, `<key> <property>:<kind>[:<arg>] ...`.
# Comment lines start with `#`.
#
# Kinds, and what the sidecar does when the property is ABSENT:
#   rand           32 random bytes, URL-safe base64, no padding (43 chars)
#   randb64        32 random bytes, standard base64 (44 chars)
#   rand8          8 random bytes, URL-safe base64, no padding (11 chars)
#   pw             43 random letters and digits (256 bits): a PASSWORD, the
#                  kind for every value a program may receive as an argument.
#                  rand starts with '-' one draw in 64, and `neo4j-admin dbms
#                  set-initial-password -Xyz` reads that as an option (exit
#                  64, blocker 3 loops #16/#18). scripts/check-seed-passwords.sh
#                  refuses password:rand.
#   ecpem:<name>   the private key of transit key <name> (ecdsa-p256), PEM
#   rsapem:<name>  the private key of transit key <name> (rsa-2048), PEM
#   rsapub:<name>  the public key of transit key <name> (rsa-2048), PEM
#   literal:<v>    the literal value <v>
#   empty          the empty string. The operator fills it in later with
#                  scripts/vanilla-set-secret.sh
#   input:<file>   the bringup keyring input mounted at /etc/openbao/inputs/<file>
#   inputjson:<f>  the property of the same name in the JSON object mounted at
#                  /etc/openbao/inputs/<f>
#   svctoken       the platform service token the sidecar minted
#
# A property that is PRESENT is never overwritten, with two exceptions:
# `input` and `inputjson` follow the keyring (a non-empty keyring value that
# differs from the stored one is written), and `svctoken` follows the token
# in the gibson-platform-operator-vault Secret. Everything else is generated
# once and kept, so an upgrade never rotates a credential under a workload.
