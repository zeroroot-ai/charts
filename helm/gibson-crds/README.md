# gibson-crds

CRDs for the gibson platform. One chart, one concern.

Ships every `CustomResourceDefinition` consumed by:
- `tenant-operator` (Tenant, TenantMember, AgentEnrollment, ComponentGrant)
- `platform-operator` (PlatformBootstrap, OIDCClient)

**Must be installed before `gibson-operators`** — controllers register CRD watches at startup; if the CRDs aren't yet present the manager fails to start.

## Lifecycle

CRDs are templated under `templates/` (not `crds/`), so `helm upgrade gibson-crds` applies new CRD versions in place. Each CRD carries `helm.sh/resource-policy: keep` so an accidental `helm uninstall gibson-crds` does NOT delete the CRDs (and every CR depending on them).

For a true wipe:

```sh
helm uninstall gibson-crds
kubectl delete crd tenants.gibson.zeroroot.ai \
                   tenantmembers.gibson.zeroroot.ai \
                   agentenrollments.gibson.zeroroot.ai \
                   componentgrants.gibson.zeroroot.ai \
                   platformbootstraps.gibson.zeroroot.ai \
                   oidcclients.gibson.zeroroot.ai
```

## Syncing from sibling repos

CRDs are generated by `controller-gen` in each sibling operator's repo. To re-sync after a CRD type change:

```sh
make sync-crds      # copies from tenant-operator + platform-operator config/crd/bases/
```

This regenerates `templates/<group>_<plural>.yaml` files. Commit them.

## Install

```sh
helm install gibson-crds . --create-namespace --namespace gibson
```
